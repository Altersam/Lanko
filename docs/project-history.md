# История развития Lanko.rf

## Контекст

Первоначальная задача — заменить три устаревших сайта питомника одним современным ресурсом. В ходе работы стало понятно, что владельцу нужен не просто новый frontend, а самостоятельная система управления контентом и заявками.

## v1 — консолидация и миграция

### Проблемы исходного состояния

- три раздельных сайта;
- дублирующая и громоздкая навигация;
- отсутствующий или слабый адаптив;
- битые страницы и медиа;
- ошибки в привязке фотографий;
- публикация зависела от разработчика;
- отсутствовала нормальная воронка заявок.

### Что было сделано

- аудит источников;
- Python ETL;
- единая WordPress-тема;
- CPT + ACF;
- каталог животных и щенков;
- родословные;
- статьи и галереи;
- услуги;
- динамические формы;
- заявки в БД;
- мини-CRM;
- календарь;
- Telegram-бот;
- импортёр.

## v2 — работа владельца без разработчика

После запуска фокус сместился с «сайт работает» на «сайтом удобно пользоваться каждый день».

### Изменения интерфейса

- «Питомцы» → **«Щенки на продажу»**;
- галерея объединена с публикациями;
- записи стали работать и как статьи, и как фотоальбомы;
- добавлена лента пород;
- карточки щенков появились на главной;
- добавлен редактор баннеров;
- контакты стали более прикладными.

### Кабинет `/app/`

Главное изменение второй итерации — собственный мобильный кабинет. Он убирает необходимость объяснять владельцу стандартную админку WordPress и даёт только нужные операции.

## v3 — production hardening

Третья итерация — техническое доведение системы:

- SEO-метаданные;
- canonical;
- Open Graph;
- sitemap;
- robots;
- Schema.org JSON-LD;
- аналитика;
- оптимизация LCP и CLS;
- WebP и кэширование;
- редактирование уже опубликованного контента из кабинета.

## Итоговая логика проекта

Проект перестал быть «редизайном сайта» и стал небольшой вертикальной цифровой платформой для питомника:

**публичный контент → заявка → CRM → календарь → уведомления → повторное управление контентом владельцем.**

## Portfolio refresh — сентябрь 2026

Публичный GitHub-репозиторий был переосмыслен как кейс:

- README сокращён и структурирован;
- история версий вынесена отдельно;
- архитектура оформлена отдельным документом;
- визуальный `index.html` переработан в интерактивную витрину;
- служебные старые HTML-имена оставлены как совместимые redirect-страницы.
