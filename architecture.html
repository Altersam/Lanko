Основные потоки

Публикация

Владелец создаёт материал через кабинет, WordPress или Telegram → данные сохраняются → публичная страница получает актуальную версию → SEO-разметка формируется автоматически.

Заявка

Посетитель выбирает услугу → видит короткую форму → заявка сохраняется → владелец получает уведомление → заявка появляется в CRM → при подтверждении даты попадают в календарь.

Исторический контент

Старые сайты разбираются скриптами → тексты и медиа очищаются → восстанавливаются связи → подготовленный датасет импортируется в WordPress.

Контур владельца

Кабинет /app/ отделён от стандартного wp-admin. В ежедневном интерфейсе остаются только нужные действия: добавить щенка, опубликовать новость, посмотреть заявки, сменить статус, открыть календарь и поменять баннер.

Принцип: CMS может быть сложной внутри, но интерфейс владельца не должен становиться сложнее после каждого нового сервиса.

Как добавить монетизацию без перестройки сайта

Коммерческий контур можно добавить поверх уже существующих заявок и CRM. Для первых тестов не нужен новый backend.

Партнёрские товары — отдельный лёгкий поток

Страница «Чем мы пользуемся» не требует корзины. В WordPress хранится карточка рекомендации: фото, короткое пояснение, категория и внешняя ссылка. Клик можно считать событием аналитики, покупка и начисление вознаграждения происходят уже на стороне партнёрской программы.

Что измерять

Не нужно внедрять сложную BI-систему. Для первого месяца достаточно четырёх событий и одной таблицы.

СобытиеКогдаЧто показывает
service_viewОткрыли страницу услугиЕсть ли интерес.
lead_submitОтправили заявкуКонверсия страницы.
booking_confirmedДоговорились об услугеСколько заявок превращается в работу.
referral_clickПерешли по партнёрской ссылкеЕсть ли смысл в рекомендациях товаров.
Самый полезный отчёт: «Источник → заявок → подтверждено → выручка». Он даст больше пользы, чем десятки красивых графиков.

Что технически не нужно строить сейчас

  • отдельный микросервис платежей;
  • свой каталог товаров и складской учёт;
  • личный кабинет клиента;
  • сложную систему тарифов;
  • маркетплейс специалистов;
  • автоматический расчёт динамических цен;
  • отдельное мобильное приложение для клиентов.

Если тест покажет реальный спрос, любой из этих слоёв можно добавить позже. Пока преимущество проекта — в том, что он остаётся маленьким и управляемым.

Публичный репозиторий

GitHub-репозиторий — портфолио и документация, а не зеркало production. Здесь не должны храниться ключи API, пароли, токены Telegram, SMTP-реквизиты, персональные данные заявителей или полная конфигурация сервера.
